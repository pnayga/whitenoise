whitenoise — User Guide

Stochastic White Noise Analysis with Memory (SWNA)
Package version 0.3.0 · Python ≥3.9 · May 16, 2026

1. Overview

whitenoise is a research package implementing Stochastic White Noise Analysis (SWNA) with Memory. The framework models a fluctuating observable as a stochastic integral driven by white noise, where a memory kernel encodes how past fluctuations influence future dynamics.

The central quantity is the Mean Square Displacement (MSD), which characterises how the spread of a fluctuating observable grows with lag Δ: 

MSD(Δ) = (1 / (N − Δ)) · ∑i=0N−Δ−1 [x(i+Δ) − x(i)]²

Fitting a theoretical SWNA model to the empirical MSD yields the memory parameter μ, which quantifies the strength and direction of memory in the system.

The package always reports μ (and its 95% confidence interval) directly. Where a result.regime classification is available, it is model-family specific — two independently sourced schemes apply to two different model families, and they are never merged into a single generic μ-only table:

  • Cosine / sine models admit a short-time (T « 1) reduction of the MSD to a power law, MSD ≈ c·Tα, with α = 2μ − 1. Classification is on α, not μ directly: α < 1 subdiffusive, α = 1 Brownian, 1 < α < 2 superdiffusive, α > 2 hyperballistic. Source: Elnar et al. (2021, Climate Dynamics).
  • Exponential model does not reduce to a clean power law over the fitting range, so the α-based labels above do not apply. Instead classification comes from the power-law scaling exponent (μ−1)/2 in the memory function f(t−τ)h(τ) = (t−τ)(μ−1)/2·e−β/2τ/τ:
    • μ = 1: exponent (μ−1)/2 = 0, so the power-law term disappears and f(t−τ)h(τ) = e−β/2τ/τ — fluctuation behavior is dominated purely by the exponential damping term: a memoryless process.
    • μ > 1: exponent (μ−1)/2 > 0, so (t−τ)(μ−1)/2 increases as t−τ increases — the memory effect of an earlier fluctuation at τ « t is stronger. Non-Markovian, long memory.
    • μ < 1: exponent (μ−1)/2 < 0, so (t−τ)(μ−1)/2 decreases as t−τ increases — the memory effect of an earlier fluctuation at τ « t is weaker (though it strengthens again as τ approaches t). Non-Markovian, short memory.
    Source: Sithi et al. (2025, Physica Scripta 100, 015243).
  • All other models (fBm and the stub models) have no automatic classification (result.regime is None) until their own reduction/source is confirmed. μ = 1 (or H = 0.5 for fBm) is always ordinary Brownian motion as a plain mathematical fact, independent of any classification scheme.
Scope: The package accepts any sequential 1D observable — not just time series. Column 1 is the independent variable (time, index, frequency, distance, occurrence number, etc.); column 2 is the observable. The term “time” is used loosely throughout this guide.

3. Quickstart

import whitenoise as wn

# --- Analyze a single CSV ---
result = wn.analyze('sunspot.csv', model='exponential')
result.summary()           # prints formatted parameter table
result.plot_all()          # three-panel figure: series, MSD, PDF

# --- Inspect data before fitting ---
time, values, meta = wn.read_csv('sunspot.csv')
wn.plot_series(time, values, metadata=meta)      # raw series
lags, msd = wn.compute_msd(values)
wn.plot_msd_empirical(lags, msd, metadata=meta)  # MSD shape check

# --- Optional detrending before analysis ---
fluct = wn.detrend(values, method='moving_average', window=11)
result = wn.analyze(fluct, model='cosine', label='Sunspot fluctuations')

# --- Compare multiple datasets ---
comparison = wn.compare({
    'Sunspots':    'sunspot.csv',
    'Earthquakes': 'earthquake_ph.csv',
}, model='exponential')
print(comparison.summary_df)
wn.publish_comparison(comparison)

# --- Batch process a folder ---
batch = wn.batch_analyze('data/xray_binaries/', model='cosine')
batch.to_csv('results.csv')

# --- Try all models on one file ---
search = wn.batch_model_search('sunspot.csv')
print(search.summary_df[['model', 'r_squared']].to_string())

7. Preprocessing (Optional)

These helpers are optional. Call them manually before analyze() if your data has a non-stationary trend or needs smoothing. The pipeline never calls them automatically unless you pass detrend_method= to analyze().

When to detrend: The SWNA framework assumes the observable represents fluctuations around some baseline. If your data has a clear long-term trend (e.g. a rising CO&sub2; baseline, a linear drift), remove it first. If the data is already fluctuating around zero, no detrending is needed.

There are also two advanced detrending functions not exposed in the standard pipeline but available in utils/preprocess.py:

  • detrend_psd(values, threshold=0.5) — Removes dominant periodic components via Power Spectral Density analysis (PSD filtering). Useful for data with strong deterministic periodic cycles.
  • detrend_fingerprint(values, cycle_length=None, trough_indices=None) — Cycle averaging (“fingerprinting”) detrending: aligns repeated cycles at their maxima, averages them, then subtracts. Useful when cycles have similar shapes but vary in timing.

8. Core Functions

compute_msd()

compute_msd(x, max_lag=None, normalize=False) -> tuple[np.ndarray, np.ndarray]

Compute the empirical Mean Square Displacement of a 1D time series.

Formula: MSD(Δ) = (1 / (N−Δ)) · ∑i [x(i+Δ) − x(i)]²

ParameterTypeDefaultDescription
xarray-like (1D)requiredFluctuating observable. Accepts ndarray, pd.Series, list. Isolated NaN values are replaced by linear interpolation before computation.
max_lagint or NoneNoneMaximum lag. Defaults to N//2. Hard-capped at N//2 (beyond N/2, each MSD estimate uses fewer than N/2 data pairs and becomes unreliable).
normalizeboolFalseIf True, divide all MSD values by MSD[0] (lag=1). Preserves the scaling exponent μ while setting the initial value to 1.

Returns: (lags, msd) — both shape (max_lag,). lags are integer steps 1…max_lag.

Raises: ValueError if input is not 1D (message: ✗ Input must be 1D. Got shape …); if fewer than 10 points (message: ✗ Need at least 10 data points. Got …); if more than 50% NaN (message: ✗ Too many missing values (…% NaN). Check your data.).

time, values, meta = wn.read_csv('sunspot.csv')
lags, msd = wn.compute_msd(values)
print(lags.shape)   # (N//2,) e.g. (150,) for 300 points

# Inspect shape before fitting
wn.plot_msd_empirical(lags, msd, metadata=meta)

9. Models

The MODELS registry contains 19 models (18 theoretical MSD formulas from the SWNA reference literature, plus the exp_plateau model from Violanda et al. 2019). Model selection is always manual — the researcher specifies model=. The package never auto-selects. Run wn.list_models() to see all models and their current status. The name 'dna' is a backward-compatible alias for 'exp_plateau'.

Model selection guidance

One model per run: analyze() fits exactly one model. Selecting the right model is the researcher’s responsibility. If unsure, start with model='exponential' (most commonly used in published SWNA studies). If your data shows clear oscillatory structure, try model='cosine'. Use wn.batch_model_search('mydata.csv') to run all available models and compare R² values side by side.
R² rangeInterpretationAction
≥ 0.8Good fitReport μ with 95% CI. Results are reliable.
0.5 – 0.8Moderate fitCaution. Report but note uncertainty. Consider another model.
< 0.5Poor fitModel is likely wrong. The package prints a ⚠ warning and suggests alternatives. Try batch_model_search().

13. Advanced Usage

Running the pipeline step by step

For full control, call each step individually:

import whitenoise as wn
import numpy as np

# Step 1: Load
time, values, meta = wn.read_csv('sunspot.csv')

# Step 2: Inspect
fig = wn.plot_series(time, values, metadata=meta, show=False)

# Step 3: Detrend (manual decision)
fluct = wn.detrend(values, method='moving_average', window=11)

# Step 4: Compute MSD
lags, msd = wn.compute_msd(fluct)

# Step 5: Inspect MSD shape
wn.plot_msd_empirical(lags, msd, metadata=meta)

# Step 6: Fit with custom initial guess
fit = wn.fit_msd(lags, msd, model='exponential',
                 p0=[1.5, 0.05],
                 max_lag_fraction=0.8)

if fit is not None:
    print(fit.summary())
    print(f'mu = {fit.params[\"mu\"]:.4f}')
    lo, hi = fit.confidence_intervals['mu']
    print(f'95% CI: ({lo:.4f}, {hi:.4f})')

Custom p0 and bounds

If the default initial guesses fail (fit returns None or R² is low), supply p0 and/or bounds based on domain knowledge. Remember: N is always appended internally — do not include it in p0 or bounds. 

# Custom p0 for cosine model (physical params mu, nu only; N appended internally)
result = wn.analyze('coral.csv', model='cosine',
                    fit_kwargs={'p0': [4.5, 0.003]})

# Custom p0 and bounds
result = wn.analyze('coral.csv', model='cosine',
                    fit_kwargs={
                        'p0':    [4.5, 0.003],
                        'bounds': ([0.5, 1e-9], [10.0, 1.0]),
                    })

Building a summary DataFrame manually

import whitenoise as wn
import pandas as pd

    'Earthquakes': 'earthquake_ph.csv',
    'Sunspots':    'sunspot.csv',
}

Methodological note: fitting method

Current fitting uses unweighted SSR (ordinary least squares), consistent with the published SWNA prior published results. A more statistically rigorous alternative would be Weighted Least Squares (WLS) with weights wΔ = N − Δ (large-lag MSD estimates are noisier, computed from fewer data pairs). WLS is not yet implemented but references for the approach include: Michalet (2010) and Vestergaard et al. (2014).

15. Genomics Extension (wn.genomics)

The wn.genomics submodule applies SWNA to genomic DNA sequences using the nucleotide separation distance approach from Violanda et al. (2019). The stochastic variable is the distance between consecutive nucleotide occurrences along the sequence. This distance sequence feeds into the standard SWNA pipeline via the exp_plateau model.

No additional dependencies required. Uses only NumPy and the Python standard library. BioPython is optional — a convenience adapter is provided.
Full documentation: See whitenoise/genomics/GENOMICS_GUIDE.html for the complete step-by-step guide with all options. This section covers the essential API.

Pipeline overview

FASTA
→

→
extract_pair()
→
compute_pair_msd()
→
fit_pair()
→
plot_pair()

Or use analyze_pair() for the full pipeline in one call. Saved MSD CSVs can be reloaded with refit_pair() to retry fitting without recomputing.

15.1 · Loading FASTA

record = wn.genomics.read_fasta_single('chromosome1.fasta')
seq_raw = record['sequence']
print(f"Length: {len(seq_raw):,} bp, ambiguous: {record['n_ambiguous']:,}")

# Remove ambiguous bases (W, N, R, Y, etc.)
seq = wn.genomics.filter_sequence(seq_raw)

15.2 · Transition distances

For a pair (from_nuc → to_nuc), distances are computed along the sequence:

  • Same-type (A→A, G→G, …): consecutive occurrences of the same nucleotide. Reproduces Violanda et al. (2019) exactly.
  • Cross-type (A→C, …): from each occurrence of from_nuc, distance to the nearest downstream to_nuc. Extension not in the original paper.
# Single pair
dist = wn.genomics.get_transition_distances(seq, 'A', 'A')

# All 16 pairs at once (more efficient than calling 16 times)
matrix = wn.genomics.get_all_transition_distances(seq)
wn.genomics.summarize_matrix(matrix)   # prints count table
dist_AA = matrix[('A', 'A')]
Model choice for off-diagonal pairs: The exp_plateau model was derived for same-type (diagonal) distances. Off-diagonal pairs (A→C, A→G, …) often yield low R² with exp_plateau. Try model='exponential' or model='cosine' for cross-type pairs.

15.3 · Step-by-step pipeline

import whitenoise as wn, os

record = wn.genomics.read_fasta_single('chromosome1.fasta')
seq = wn.genomics.filter_sequence(record['sequence'])

# Step 1: Extract distances (save for later)
dist = wn.genomics.extract_pair(seq, 'A', 'A', save_path='AA_distances.csv')

# Step 2: Compute MSD (save to avoid recomputing)
lags, msd = wn.genomics.compute_pair_msd(
    dist, max_lag=1500, save_path='AA_msd.csv'
)

# Step 3: Fit
fit = wn.genomics.fit_pair((lags, msd), model='exp_plateau')
print(f"R² = {fit.r_squared:.4f}")

# Step 4: Plot
fig = wn.genomics.plot_pair(lags, msd, fit,
                            title='A→A | exp_plateau model',
                            save_path='AA_fit.png')
Choosing max_lag: The exp_plateau model saturates at L ≈ 3/b. With bacterial reference b ≈ 0.0024, saturation is near L = 1250. max_lag=1500 is a safe default that captures the full curve.

15.6 · The exp_plateau model

MSD(L) = a − c · exp(−b · L)
ParameterRoleTypical range (bacterial)
aPlateau height — MSD approaches a as L → ∞3–8
bExponential decay rate — how fast MSD rises to plateau0.001–0.01
cAmplitude of exponential term; must satisfy c < a2–6
NNormalization scalar — fitted automatically∼1

Published reference values (Violanda et al. 2019, bacterial genomes): a ≈ 5.21, b ≈ 0.0024, c ≈ 3.81

No μ parameter. The exp_plateau model describes restricted diffusion (bounded MSD plateau) via the a, b, c parameters instead. The backward-compatible alias model='dna' also works.

15.7 · Batch analysis (all 16 pairs)

import whitenoise as wn, os

16. RadioJOVE Extension (wn.radiojove)

The wn.radiojove submodule applies SWNA to radio burst observations recorded with a RadioJOVE spectrograph. The stochastic variable is the Z-score normalized intensity of a selected burst region sampled at a fixed cadence (0.1 s or 1.0 s). The memory parameter μ quantifies the dynamical memory structure of the burst.

Full documentation: See whitenoise/radiojove/RADIOJOVE_GUIDE.html for the complete guide including the preprocessing GUI workflow, multi-resolution comparison, and troubleshooting. This section covers the essential API.

16.1 · CSV format and filename convention

The GUI exports CSVs with two columns and filenames following this pattern:

YYMMDDHHMMSS<Station>_region_<N>_<cadence>s.csv

Example:
  230728154000Higgins_Home_region_1_0.1s.csv   ← 0.1 s cadence
  230728154000Higgins_Home_region_1_1.0s.csv   ← 1.0 s cadence

Column 1: time in seconds. Column 2: Z-score normalized intensity (mean=0, std=1).

Why two cadences? Running SWNA on both 0.1 s and 1.0 s files and comparing μ values confirms that the memory structure is robust to temporal resolution. Use 1.0 s as the primary result and 0.1 s as validation. See Section 16.5.

out = wn.radiojove.analyze_burst(
    '230728154000Higgins_Home_region_1_0.1s.csv',
    model='exponential',
    detrend_method='linear',    # recommended default
    output_dir='swna_results/', # saves plot PNG here
)

result = out['result']

    print(f"mu     = {result.fit.params['mu']:.4f}")
    print(f"R2     = {result.fit.r_squared:.4f}")

out['figure'].show()   # dual-panel MSD plot (linear + log-log)
Model choice: Use model='exponential' for Type III solar bursts and most Jovian S-bursts — these have monotonically growing MSDs. The cosine model fails catastrophically (R² ≈ −1060) on monotonic MSDs.

16.5 · Multi-resolution comparison (0.1 s vs 1.0 s)

import pandas as pd

groups = wn.radiojove.group_by_cadence(paths)

df_01s = wn.radiojove.batch_analyze_bursts(groups[0.1], model='exponential', verbose=False)
df_10s = wn.radiojove.batch_analyze_bursts(groups[1.0], model='exponential', verbose=False)

df_01s['cadence'] = '0.1s'
df_10s['cadence'] = '1.0s'

df_all = pd.concat([df_01s, df_10s], ignore_index=True)
print(df_all[['dataset', 'cadence', 'mu', 'r_squared']])
If μ at 0.1 s and 1.0 s agree within their 95% confidence intervals, the memory structure is robust. A discrepancy suggests resolution-dependent effects.

16.7 · The exponential SWNA model for radiobursts

MSD(T, mu, beta) = Gamma(mu) * beta^(-mu) * T^(mu-1) * exp(-beta / T)
ParameterRoleTypical range (Type III bursts)
μMemory exponent — controls MSD growth rate1.4–1.7
βExponential decay rate10–100
NNormalization scalar∼1

Type III solar bursts are driven by semi-relativistic electron beams spiralling along open coronal magnetic field lines, producing positively correlated intensity fluctuations consistent with μ ≈ 1.4–1.6 (superdiffusive).

18. Known Limitations

1. Stub models. Nine models in the MODELS registry raise NotImplementedError when called: exp_whittaker, bessel_K, hypergeom_F1, bessel_I, hypergeom_3F2, csc_power, cot_power, bessel_pair, bessel_pair2. Use wn.list_models() to see current status.
2. Unweighted fitting. The current fitting uses ordinary least squares (unweighted SSR). Statistically, WLS with weights wΔ = N − Δ would be more rigorous (large-lag MSD estimates are noisier). Not implemented, but kept consistent with prior published results from the Bernido group.
3. Parallel n_jobs > 1 requires CSV paths. When n_jobs > 1 is specified in batch_analyze(), all jobs must use CSV file paths. In-memory arrays cannot be reliably passed to parallel worker threads.
4. Oscillatory model NaN regions. The cosine and sine models return nan where cos(νT/2) ≤ 0 or sin(νT/2) ≤ 0 respectively (the formula produces a non-positive MSD there, which has no physical meaning). If your MSD plot shows gaps, this is expected. Consider using a smaller lag range with max_lag_fraction, or try a different model.
5. Minimum data length. compute_msd() requires at least 10 data points. Fewer than ~50 points will produce very noisy MSD estimates and unreliable fits. Published results typically use N ≥ 200 points.
